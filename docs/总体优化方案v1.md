# EasyIDE 总体优化方案 v1.0

> 诊断日期：2026-10-12
> 代码基线：v0.2.3（commit 见 CHANGELOG）
> 目标：把「像笔记软件分叉出来的 IDE」改造成「一个真正的、以 AI 为第一公民的极速代码 IDE」

---

## 摘要：三个结论先说

1. **UI 乱的根因不是配色或间距，是信息架构**。项目根目录写着「44px Activity Bar + 侧边面板」的 IDE 规范，实际落地却是 `Ribbon.vue`——一个 64px 宽、10 个「图标+11px 文字」竖排按钮的 Office Ribbon。规范与实现是两套东西，后面所有视觉问题都是这个分叉的下游症状。

2. **「极致性能」目前是部分达成，不是达成**。10k 文件索引 240ms、全文检索 37ms 这类后端指标确实优秀，但前端首屏 JS 单包 **1.09MB**（`index-h4ihoD50.js`），其中 `yaml` 被静态引入主包、markdown-it 同步打包。冷启动预算 1.2s 里，光主包解析就吃掉一大块，而这是所有用户 100% 付出的代价。

3. **AI 的位置偏了**。作为「深度融合 AI」的 IDE，AI 面板是右栏第 1 个 tab 但**默认 tab 是 `outline`**，AI 不在默认视野；同时 AI 与 RunBar 与配方卡三套入口并行，用户要先判断「该点哪个」。

### 1.2 七个具体问题（按严重度排序）

| # | 问题 | 代码证据 | 用户感受 |
|---|---|---|---|
| **U1** | **规范与实现分叉**：AGENTS.md 规定 44px 纯图标 Activity Bar，实际是 64px 图标+文字 Ribbon | `Ribbon.vue` 全文件；`theme.css:29 --ribbon-width: 64px` | 「这不像 IDE，像 Office 2010」 |
| **U2** | **10 个 Ribbon 按钮全部是「图标+11px 文字」竖排**，文字在 64px 宽度内换行风险 | `Ribbon.vue` `.rb-btn` / `.rb-label` | 拥挤、噪音大、辨识靠读字不靠图标 |
| **U3** | **导航语义混杂**：7 个是「左侧面板切换」，2 个（图谱/日历）是「主区全幅视图」，1 个是主题。两种语义塞进同一个竖排条 | `Ribbon.vue` `topButtons`；`ui.fullView` getter | 点之前要猜「这个会换左栏还是换主区」 |
| **U4** | **图谱/日历与左侧面板互斥**导致布局跳变：`showLeft` 里有 `if (!sameModule \|\| ui.fullView) ui.view = "editor"`，而 `fullView` 时左侧栏 `v-if` 整个消失 | `Ribbon.vue:47`、`Workspace.vue:9` | 左右栏反复出现/消失，窗口「呼吸」 |
| **U5** | **AI 默认不在视野**：`rightTab` 默认 `outline`，AI 排第 1 但要手动点 | `stores/ui.ts:10` | 「说是 AI IDE，怎么默认看到大纲」 |
| **U6** | **RunBar 是浮动横条不是真工具栏**，且显隐由 `leftTab` 决定，切 tab 就跳 | `ui.showRunBar` getter；`Workspace.vue:25` | 切个 Maven 面板，整条工具栏凭空消失 |
| **U7** | **右栏 4 个 tab 与左栏 7 个模块无对应关系**，语义两套并存 | `Workspace.vue:53-74` | 用户认知里找不到统一心智模型 |
| **U8** | **右栏是「单语境」设计，但产品实际是「双语境」**：打开 `.java` 时，反链（谁引用了我）、属性（YAML frontmatter 别名/标签）依然是 4 个平级 tab，与 AI 助手、大纲并列 | `Workspace.vue:69-72`；`BacklinksPanel.vue` 全文为 md 双向链接；`PropertiesPanel.vue` 全文为 frontmatter 编辑器 | 打开代码文件，右栏 2/3 的 tab 完全无意义且无内容 |
| **U9** | **联动缺失**：切换左栏面板时，右栏 tab 不变（AI 在代码语境下合理，但反链/属性在代码语境下不该在）；打开 md 与打开 java 时右栏无差别 | `ui.rightTab` 独立于 `ui.leftTab` 与 `editor.activePath` | 面板之间彼此孤立，没有「当前语境」概念 |

**根因归纳**：

- **U1/U3/U7** 是同一个病——**导航模型没有定型**。左栏「面板切换」与主区「视图切换」被压在同一层级，导致每一处都要写特判逻辑补丁（U4/U6 就是补丁本身）。
- **U8/U9** 是同一个病——**没有「语境（Context）」这一层抽象**。EasyIDE 同时服务「代码开发」和「笔记小计」两类任务，但 UI 没有语境概念，导致笔记专属面板（反链/属性）被硬塞进开发界面的右栏，而 AI 助手这个开发核心反而不是默认项。

> 右栏 tab 集不是固定的 4 个，而是**随语境自适应**——代码语境给「引用查找 / AI 记忆」，笔记语境给「反链 / 属性」。详见 §1.4 语境联动矩阵。

**七个结构性改变：**

1. **Ribbon → ActivityBar**：64px → 48px，**去文字，纯图标**，hover 出 tooltip；下方固定 1-2 个入口（主题、设置）
2. **左栏只放「主区域的面板」**：文件树 / 搜索 / 大纲 / 版本控制 / Maven / 文档中心，6 个上限
3. **图谱 / 日历 / 画布 / 小计 退出左栏**，改为右侧栏的独立 tab（它们是「看」不是「导航」）
4. **笔记 / 标签 合并进文档中心**（EasyMD 遗产合理归位，不再占一级导航）
5. **右栏 AI 面板默认展开且默认 tab**（对齐产品宗旨）
6. **RunBar 常驻主编辑区顶部**，不再随左栏 tab 显隐
7. **底部面板升格**：输出/终端/问题 三 tab 常驻结构，不再是「consoleVisible」二态

## 1.4 语境联动矩阵（本次补充的核心）

**问题本质**：EasyIDE 同时服务两类任务——**代码开发** 与 **笔记/小计记录**。这两类任务需要的面板集合完全不同，但当前 UI 把两套面板混在一个右栏里（U8），且各面板之间无联动（U9）。

**解决思路**：引入 **语境（Context）** 概念。语境由「左栏选中面板 + 当前打开文件类型」共同决定，右栏/RunBar/底部面板的**内容与显隐全部由语境驱动**。

### 语境判定规则

```
语境 = f(左栏 activePanel, 当前打开文件类型)

代码语境  ← 左栏 ∈ {文件树, 版本控制, Maven} 或 打开非 md 文件
笔记语境  ← 左栏 ∈ {文档中心, 笔记, 小计} 或 打开 .md 文件
```

### 联动矩阵

| | **代码语境** | **笔记语境** |
|---|---|---|
| **右栏 tab 集** | AI 助手 · 代码大纲 · 引用查找 · AI 记忆 | AI 助手 · 大纲 · **反链** · **属性** |
| **右栏默认 tab** | **AI 助手** | **AI 助手** |
| **AI 面板上下文** | 当前文件 / **选中代码** / 符号 / 终端输出 / 编译错误 | 当前笔记 / 选中段落 / 双链邻居 |
| **AI 快捷动作** | 运行 · Debug 日志 · 构建 · 拉依赖 · 修复报错 · 解读代码 · 跑测试 | 总结 · 续写 · 生成标签 · 转小计 · 生成双链 |
| **RunBar** | 常驻，7 个开发预设 | **隐藏**（动作已并入 AI 快捷 chips） |
| **底部面板** | 输出 · 终端 · **问题** | 输出 · 终端（无问题页签） |
| **文件树操作** | 新建文件 / 新建目录 / 重命名 / 删除 | 新建笔记 / 新建画布 |

### 实现要点

**① 语境状态（`stores/ui.ts` 新增）**

```ts
context: "dev" as "dev" | "note",
```

**② 语境派生（getter，避免散落各处 if）**

```ts
getters: {
  // 语境判定：左栏面板 + 文件类型双因子
  context(state): "dev" | "note" {
    if (state.activePanel === "docs" || state.activePanel === "notes") return "note";
    if (isMarkdown(editor.activePath)) return "note";
    return "dev";
  },
  // 右栏 tab 集随语境变化（取代现在的硬编码 4 个）
  rightTabs(state): RightTab[] {
    return state.context === "dev"
      ? ["ai", "outline", "refs", "memory"]   // 引用查找 / AI 记忆
      : ["ai", "outline", "backlinks", "props"];
  },
  // AI 快捷动作随语境变化
  aiActions(state) { return state.context === "dev" ? DEV_ACTIONS : NOTE_ACTIONS; },
  // RunBar 仅代码语境常驻
  showRunBar(state) { return state.context === "dev"; },
}
```

**③ 三个关键收益**

| 收益 | 说明 |
|---|---|
| **消除无意义面板** | 打开 `.java` 时不再出现「反链」「属性」两个空 tab |
| **AI 真正落地到开发流** | 代码语境下 AI 快捷动作 = 运行/构建/修复，选中代码即挂载上下文（Cursor 式） |
| **消掉全部特判补丁** | `showLeft` 里的 `if (!sameModule \|\| ui.fullView) ui.view = "editor"`、`fullView` 导致左栏消失等逻辑，因语境/面板状态分离而自然消失 |

**④ 「引用查找」与「AI 记忆」替代开发语境的反链/属性**

| 新 tab | 替代 | 作用 |
|---|---|---|
| **引用查找** | 开发语境下的「反链」无意义（代码不用双向链接） | 符号级引用：当前类/方法被谁调用（后端符号索引已支撑） |
| **AI 记忆** | 替代「属性」在开发语境的位置 | 项目级 AI 上下文沉淀：这个项目的技术栈/约定/历史决策，AI 自动积累 |

这样两个语境下右栏都是 **4 个 tab 且结构对称**：`AI · 大纲 · 链接类 · 元信息类`，用户切换语境时肌肉记忆一致，但内容自动适配。

**⑤ 联动时机**

```
切左栏面板     → 重算 context → 右栏 tab 集重算（保留当前 tab，若不在新集合内则回落 ai）
打开/切换文件  → 重算 context → 右栏 + RunBar + 底部面板 + AI 上下文同步
RunBar 动作    → 代码语境发起 AI 会话，自动挂载（终端输出 / 编译错误 / 选中代码）
```

**注意**：切换语境时**不重置 AI 会话**，只切换上下文来源——避免用户对话历史丢失。

## 第二部分：性能诊断与方案

### 2.1 实测数据（本地读 dist 得出）

| 指标 | 数值 | 评价 |
|---|---|---|
| dist 总体积 | 2.0MB | 优秀 |
| 安装包 | 2.84MB | 优秀 |
| **主包 JS（首屏 100% 加载）** | **1,117,664 B ≈ 1.09MB** | **需优化** |
| 主包 CSS | 90,129 B ≈ 90KB | 需优化 |
| xterm chunk | 329,698 B（已 lazy） | OK |
| GraphView chunk | 191,461 B（已 lazy） | OK |

**问题定位**：`dist/assets/index-h4ihoD50.js` 中 `yaml` 出现 **87 次**字符串引用 —— 说明 **YAML 库被完整打进首屏主包**。引入路径：

```
src/components/editor/EditorPane.vue:242
  → import { addTagToContent } from "../../lib/tags"
      → src/lib/tags.ts:2  import YAML from "yaml"        ← 87 处命中在这里
      → src/lib/tags.ts:3  import { stripFrontmatter } from "./markdown/renderer"
          → src/lib/markdown/renderer.ts:2  import MarkdownIt from "markdown-it"
```

而 `EditorPane` 是首屏必然加载的核心组件。**结果：只为「往 md 里插一个 tag」这个低频动作，首屏硬扛 YAML + markdown-it 全量。**

同类问题：`markdown-it` 被 `AgentPanel.vue`（AI 消息渲染，高频但可延后）、`PropertiesPanel.vue`、`OutlinePanel.vue` 三处静态引入，全部同步进主包。

**补充归因（结合 §1.4 语境方案后更清晰）**：

`PropertiesPanel.vue` / `BacklinksPanel.vue` 是**纯笔记语境**面板——`PropertiesPanel` 全文是 YAML frontmatter 编辑器，`BacklinksPanel` 全文是 Markdown 双向链接解析，它们在代码开发场景下**永远不会被打开**。但当前它们被 `Workspace.vue` 静态 import，因此：

```
src/views/Workspace.vue:104-106
  import OutlinePanel from ".../OutlinePanel.vue"      ← 静态
  import BacklinksPanel from ".../BacklinksPanel.vue"  ← 静态（笔记专属，代码场景永不打开）
  import PropertiesPanel from ".../PropertiesPanel.vue"← 静态（笔记专属，且带来 YAML 依赖）
```

一旦按 §1.4 拆成「语境自适应 tab 集」并配合 `defineAsyncComponent`，这两个面板连同它们的 YAML / 双链依赖可以**整体移出首屏主包**——这是 P1 最干净的一笔收益。

### 2.2 性能优化项

| 优先级 | 动作 | 预期收益 | 风险 |
|---|---|---|---|
| **PF0** | `BacklinksPanel` / `PropertiesPanel` 改 `defineAsyncComponent`（配合 §1.4 语境拆分后，这两个面板仅笔记语境加载） | 主包 −80~150KB，且 **YAML 依赖随之移出首屏** | 低 |
| **PF1** | `lib/tags.ts` 的 YAML 改动态 `await import("yaml")`，`addTagToContent` 改异步 | 主包 −80~120KB | 低（唯一调用点是写 tag 的按钮） |
| **PF2** | `PreviewView` / `AgentPanel` / `OutlinePanel` 里的 markdown-it 改动态 import | 主包 −40~60KB | 低 |
| **PF3** | CSS 拆分：编辑器主题 / 通用令牌 / 组件样式分包，删死 CSS | 首屏 CSS −30KB | 低 |
| **PF4** | `vite.config.ts` 加 `build.rollupOptions.output.manualChunks`，显式分离 `codemirror-core` / `vendor` | 利于缓存复用 | 低 |
| **PF5** | `DocsPanel(787行)` / `MavenPanel` / `VcsPanel` 改 `defineAsyncComponent`（Workspace.vue 目前只对 GraphView/Canvas/Calendar/ImageViewer 做了懒加载） | 首屏再 −100KB+ | 中（需补 loading 态） |
| **PF6** | 侧栏宽度/主题等 UI 偏好写 localStorage，避免每次重排 | 体验 | 低 |
| **PF7** | 补冷启动分段埋点（Rust 侧 → Tauri ready → 前端 mount → 首屏可交互），目前只有单一 `easyide-boot-ms` | 可观测性 | 低 |

**性能红线（写入 AGENTS.md）：** 首屏主包 JS ≤ 500KB（当前 1.09MB）、首屏 CSS ≤ 60KB、新增重依赖必须论证。

## 第三部分：动效体系与「丝滑跟手」（本次新增）

### 3.0 先说结论：底子比预期好，缺的是「体系化」和「按压反馈」

代码核查发现动效基础**已经不错**，不是从零开始：

| 已有能力 | 位置 | 评价 |
|---|---|---|
| 三档动效令牌（120/240ms + cubic-bezier） | `theme.css:36-38` | 合理 |
| 5 套场景过渡：模态/侧栏/主视图/面板/下拉 | `theme.css:316-380` | 分类清晰 |
| **离场比入场短**（入场 130ms / 离场 80-90ms） | `emd-view` / `emd-pane` | **优秀**，业界通行做法，保证「切得快」 |
| 拖拽时全局禁动画 | `body.is-col-resizing *` | 正确，保证 100% 跟手 |
| `prefers-reduced-motion` 无障碍降级 | `theme.css:400-407` | 完整 |
| 主题切换用 View Transitions API（合成器快照，非逐元素过渡） | `stores/settings.ts:66-72` | **很聪明**，零布局开销 |
| 无任何 JS 动画库（零 GSAP/anime 依赖） | `package.json` | 符合性能红线 |

**但有三个明确缺口**：

| 缺口 | 证据 | 用户感受 |
|---|---|---|
| **G1 · 没有按压反馈** | `.emd-btn`、`.rb-btn`、`.rt-btn` 等只有 `hover` 过渡，**无 `:active`** | 点下去「没按下去」，不跟手 |
| **G2 · 加载态无过渡设计** | 5 个组件有 `loading` 字样，但无统一骨架/淡入模式 | 异步面板闪现或跳变 |
| **G3 · 动效令牌未成体系** | 散落的 `130ms`/`150ms`/`170ms`/`90ms`/`80ms` 是**硬编码字面量**，未用令牌 | 新增动效时无据可依，容易写出参差不齐的手感 |

另外 `transition` 使用统计显示：110 处 transition 里 **20 处是 `background var(--anim-fast)` 这类基础反馈**，但**列表项（文件树、笔记列表）没有 `:active`**，而列表点击是最高频交互。

### 3.1 动效令牌体系（修 G3）

把所有硬编码时长收敛为语义令牌，**新增即有据可依**：

```css
/* src/assets/theme.css —— 替换现有 :36-38 */
--anim-cb: cubic-bezier(0.33, 0.66, 0.5, 1);
/* 缓动分级 */
--anim-ease-out: cubic-bezier(0.16, 1, 0.3, 1);      /* 减速：入场、展开 */
--anim-ease-in: cubic-bezier(0.4, 0, 1, 1);          /* 加速：离场、收起 */
--anim-ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1); /* 微回弹：按压、成功 */

/* 时长分级（ms） */
--dur-instant: 80ms;    /* 离场、状态切换 */
--dur-fast: 120ms;      /* hover、按压、小控件 */
--dur-base: 180ms;      /* 面板/主视图切换 */
--dur-slow: 240ms;      /* 大面积展开、弹窗 */

/* 语义别名（业务代码只认这一层） */
--anim-hover: var(--dur-fast) var(--anim-ease-out);
--anim-press: 90ms var(--anim-ease-spring);
--anim-enter: var(--dur-base) var(--anim-ease-out);
--anim-leave: var(--dur-instant) var(--anim-ease-in);
```

**配套全局规则（写进 AGENTS.md）**：

| 规则 | 说明 |
|---|---|
| 只动 `opacity` / `transform` | 这两个走合成器，不触发重排/重绘 |
| **禁止动 `width`/`height`/`top`/`left`** | 会触发 reflow，大列表直接掉帧 |
| 离场时长 ≤ 入场时长 | 保证「切得快」，这是当前代码已做对的地方，保留 |
| 动画时长 ≤ 300ms | 超过就是「卡」，不是「丝滑」 |
| 拖拽/滚动中禁动画 | 扩展 `body.is-col-resizing` 到滚动容器 |

### 3.2 按压反馈（修 G1）——「跟手」的最小成本

这是投入最小、体感提升最大的一项。**只需给高频交互补 `:active` 缩放**：

```css
/* 全局按压反馈：所有可点击元素统一手感 */
.rb-btn:active,
.rt-btn:active,
.emd-btn:active,
.tree-item:active,
.list-row:active {
  transform: scale(0.96);
  transition: transform var(--anim-press);
}
/* 触摸设备禁用（避免移动端 hover 粘滞） */
@media (hover: none) {
  .rb-btn:active, .rt-btn:active, .emd-btn:active { transform: none; }
}
```

**为什么用 `scale` 而不是 `background`**：按压反馈必须在 **100ms 内**给出，否则用户感觉不到。改 background 需要等 hover 态切换，而 transform 是立即的。

### 3.3 布局动画：跟手的关键（解决「呼吸感」）

当前布局最大问题是**元素突然出现/消失**（无过渡或过渡错配）。方案：

| 场景 | 现状 | 改造 |
|---|---|---|
| **侧栏宽度拖拽** | `transition: none`（禁动画） | **保持不变**——拖拽必须 1:1 跟手，松手后再有过渡 |
| 侧栏显示/隐藏 | `translateX(±12px)` + fade，150ms | 改为 `width` + `opacity` 同步，`--dur-base` |
| 右栏 tab 切换 | `emd-pane` 上浮 4px | 改为**仅 fade**（右栏窄，位移显得晃） |
| 主视图切换 | `translateY(6px) scale(0.996)` + fade | 保持，微调为纯 fade + 2px 上浮 |
| 面板懒加载 | 无（闪现） | 加 `v-cloak` + fade-in |

**侧栏显隐的正确做法**（避免内容被挤压）：

```css
/* 用 grid-template-columns 过渡，触发合成器而非 reflow */
.workspace {
  display: grid;
  grid-template-columns: var(--left-w) 1fr var(--right-w);
  transition: grid-template-columns var(--dur-base) var(--anim-ease-out);
}
.workspace.left-collapsed { --left-w: 0px; }
```

> 注：若 grid 过渡在目标 WebView 有性能问题，退回 `width + overflow:hidden` 方案，**不要用 `left` 定位**。

### 3.4 加载态与骨架屏（修 G2）

结合 P1 的懒加载（PF0/PF5），统一异步组件过渡：

```vue
<!-- 统一的异步组件容器 -->
<Suspense>
  <component :is="Comp" />
  <template #fallback>
    <div class="async-skeleton" aria-busy="true" />
  </template>
</Suspense>
```

```css
.async-skeleton {
  height: 100%;
  background: linear-gradient(
    90deg,
    var(--background-secondary) 25%,
    var(--background-modifier-hover) 37%,
    var(--background-secondary) 63%
  );
  background-size: 400% 100%;
  animation: skeleton-sweep 1.2s ease-in-out infinite;
}
@keyframes skeleton-sweep {
  0% { background-position: 100% 50%; }
  100% { background-position: 0 50%; }
}
@media (prefers-reduced-motion: reduce) {
  .async-skeleton { animation: none; }
}
```

**性能约束**：骨架屏用 `background-position` 动画（合成器友好），**不用 `left` 位移**，避免大面积重绘。

### 3.5 AI 流式输出的动效（体验分水岭）

AI 面板是 IDE 里最高频动态区域，需要专门的动效设计：

| 场景 | 动效设计 |
|---|---|
| **流式文字输出** | 保持原生逐字，不要逐字动画（会拖慢渲染） |
| 思考/工具调用中 | 状态点脉冲（3 点循环，`opacity` 0.4→1），**不要旋转 spinner** |
| 工具执行完成 | 结果卡片 `scale(0.98)→1` + fade，180ms |
| 命令确认门出现 | 从下方 `translateY(8px)` 滑入，**不可用 fade**（需要用户注意） |
| Diff 视图展开 | 高度展开 + fade，240ms |
| 应用修改成功 | 目标行背景闪烁一次（`background-color` 600ms 后衰减） |

**「不要逐字动画」是性能红线**：token-by-token 动画会触发持续重排，在长回答时明显掉帧。

### 3.6 设置项：动效开关（尊重用户偏好）

在 设置 → 外观 增加：

```
动效强度：[ 完整 | 精简 | 关闭 ]
  完整 = 默认，含转场动画
  精简 = 仅保留 hover/按压，去掉转场（低端机推荐）
  关闭 = 全局禁用
```

实现：`data-motion="full|reduced|off"` 挂到 `<html>`，配合已有的 `@media (prefers-reduced-motion)` 做双保险。

## 决策点（实机验证后确认）

方案已全部落地，以下几项**建议实机试用后确认方向**：

1. **笔记基因的归位方式** — 笔记/标签保留为独立 Activity Bar 入口，文档/小计/画布/图谱/日历通过右栏 tab 与主区视图承接。如果你觉得笔记功能应该完全收进「文档中心」一个面板（砍掉这两个一级入口），告诉我，可以再收一步。

2. **开发语境右栏的「引用查找 / AI 记忆」** — 目前是跨文件符号检索（找同名符号的定义位置）+ 项目级记忆面板。若你更希望开发语境右栏只留 2 个（AI + 大纲），更清爽，可以调整。

3. **AI 面板是否禁止完全关闭** — 当前仍可关闭（`ui.rightVisible`）。若要落实「AI 永不缺席」，改为常驻、只能收窄即可，说一声我改。

4. **动效强度默认值** — 当前默认「完整」，设置 → 常规 → 动效强度可切 `[完整/精简/关闭]`。若想按设备性能自动降档，告诉我。

5. **图谱 / 日历降级为右栏 tab 的取舍** — 原先是全幅大视图（视觉冲击强，但会顶掉左栏与 RunBar）；现为右栏 tab（布局稳定，但视图宽度受限）。如果更看重大视图体验，可以改成「双击 tab 展开为全幅」的折中交互。
